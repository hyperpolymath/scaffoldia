*Single normative source.* The grammar for the files described below is
`deed/spec/DEED-GRAMMAR-SPEC.adoc` in
https://github.com/hyperpolymath/standards[hyperpolymath/standards] — the only
place the syntax, semantics and typechecking rules are defined. The next
sentence is a deliberate, *non-normative* reminder, repeated across this tree
because its absence from the family's documentation is the measured cause of the
TOML-shaped divergence now found across the estate; where it and the spec ever
disagree, the spec governs and this sentence is the error. DEED is an
*s-expression* format: there is no `key = value` production and no `[section]`
production; the only bracket is `(`. The format formerly called A2ML is now
*DEED* (`.deed`); the files here still carry `.a2ml` pending a single atomic
estate-wide rename, so do not hand-convert them. That spec path lands when
https://github.com/hyperpolymath/standards/pull/752[standards PR #752] merges.

*Unresolved citations, recorded not repaired.* The Contents list below names
`must/Mustfile`, `trust/Trustfile.hs`, `dust/Dustfile` and `intend/Intentfile`.
None of those four paths exists in this directory. What is actually here is
`Mustfile.a2ml`, `Trustfile.a2ml`, `Adjustfile.a2ml` and `Intentfile.a2ml` at
the top level, `bust/Bustfile.a2ml`, `dust/Dustfile.a2ml`, and a `Justfile`.
The verb-directory layout, the `.hs` extension and the missing Adjust and Bust
entries are each open work under the contractile layout and extension rulings;
the list is left as published rather than silently rewritten.

The *Fill-In Instructions* below are unresolved for the same reason and are
*not actionable as written*: they direct the reader to edit `Mustfile`,
`Trustfile.hs`, `Dustfile` and `Intentfile`, none of which exist here. Read them
as a record of the layout this directory was stamped from. The files actually
present are `Mustfile.a2ml`, `Trustfile.a2ml`, `Adjustfile.a2ml` and
`Intentfile.a2ml` at the top level, plus `bust/Bustfile.a2ml` and
`dust/Dustfile.a2ml`.
====

This directory contains the generalized contractiles templates. Copy the `.machine_readable/contractiles/` directory into a new repo to establish a consistent operational, validation, trust, recovery, and intent framework.

== Fill-In Instructions

1. Update the Mustfile to reflect your real invariants (paths, schema versions, ports).
2. Replace Trustfile.hs placeholders with your actual key paths and verification commands.
3. Adjust Dustfile handlers to match your rollback and recovery tooling.
4. Update Intentfile to mirror the roadmap you want the system to evolve toward.

== Contents

* `must/Mustfile` - required invariants and validations.
* `trust/Trustfile.hs` - cryptographic verification steps.
* `dust/Dustfile` - rollback and recovery semantics.
* `intend/Intentfile` - future intent and roadmap direction.
